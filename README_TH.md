# MuMu Pattern Studio

โปรแกรม Windows สำหรับอัดและเล่น Jump/Slide/Tap/Hold บน MuMu ผ่าน ADB โดยเน้นใช้ง่าย, จังหวะหลักไม่ถูกสุ่ม และหยุดฉุกเฉินได้ทันที

## รอสุ่มทักษะอัตโนมัติก่อนเริ่มเกม

ถ้าช่วง Pre Sync มีการสุ่ม Random Boost ให้เพิ่ม Event ชนิด `adaptive_wait` หลังคำสั่งเริ่มสุ่ม แล้วคง Event Tap กด Play เดิมไว้เป็น Event สุดท้ายของ `pre_sync` ระบบจะเริ่มเฝ้าปุ่ม Stop ตั้งแต่ Adaptive: ถ้าสุ่มได้ก่อนเวลา Tap เดิมจะกด Play ทันที แต่ถ้าถึงเวลาเดิมแล้วยังไม่ได้ ระบบจะรอต่อจนได้แล้วจึงกด Play

วิธีที่ง่ายที่สุดคือเลือก Tap กด Play ตัวสุดท้ายที่อัดไว้ → แก้ Type เป็น `adaptive_wait` ระบบจะแยก Tap Play เดิมเก็บไว้เป็น Event สุดท้ายให้อัตโนมัติ และย้าย Adaptive มาอยู่หลัง Pre Sync Event ก่อนหน้า จากนั้นกรอก “จุดตรวจ Stop X/Y” เป็นจุดกลางปุ่ม Stop ตามพิกัด ADB ของ MuMu (ปกติ 1280×720) ค่า `หมดเวลา = 0` หมายถึงรอได้ไม่จำกัด และกด F8 เพื่อหยุดได้เสมอ

ค่า Pre Sync Extra ยังคงทำงานหลังระบบกด Play และ Loop Delay ยังคงทำงานระหว่างรอบตามเดิม ระบบไม่ได้บังคับแก้ค่าทั้งสองช่อง

## Safe Zone แบบสองทางและจัดการ Event จำนวนมาก

Required Jump/Slide ที่ถูก Safe Zone ครอบจะเปลี่ยนเป็น Safe Random อัตโนมัติ พร้อมจำ Action และระยะ Slide ต้นฉบับไว้ หากย่อหรือย้าย Zone จนไม่ครอบ Event ที่ระบบแปลงให้อีก Event จะกลับเป็น Required เดิมอัตโนมัติ Safe Random ที่ผู้ใช้สร้างเองจะไม่ถูกเปลี่ยนกลับโดยเดา Action

คลิกเส้น Event บน Timeline เพื่อเลือกแถวเดียวกันในตารางและเลื่อนหน้าไปหา Event นั้นทันที สำหรับ Event หลังจบเกม กด “เลือก Post-game ทั้งหมด” แล้วใช้ Ctrl/Shift ปรับรายการ ก่อนกด “ลบที่เลือก” ระบบจะแสดงจำนวนและ phase ให้ยืนยันก่อนบันทึก

ค่าเริ่มต้นที่ระบบเสนอจากหน้าจอตัวอย่างคือ Stop `(1040,672)` ส่วน Event Tap Play เดิมควรอยู่ประมาณ `(930,610)` แต่ควรตรวจและแก้ให้ตรงกับหน้าจอจริงของแต่ละเครื่อง

ค่าตั้งต้นของเครื่องนี้:

- MuMu instance: `#1` / `Android Device-1`
- Candidate ports: `5557,16416` (โปรแกรมจะลองทั้งสองพอร์ต)
- ความละเอียดเป้าหมาย: `1280×720`
- พิกัดจากภาพเกม: Jump `160,635`, Slide `1115,635`
- Pause ROI จากภาพ: `x=1165, y=5, width=62, height=62`
- Pause template เริ่มต้น: `templates/default_pause_1280x720.png`
- Result XP ROI: `x=155, y=450, width=130, height=75`
- Result XP template: `templates/default_result_xp_1280x720.png`
- โปรแกรมจะพยายามค้นหา `adb.exe` ของ MuMu ให้อัตโนมัติ หากหาไม่พบให้เลือกไฟล์ด้วยปุ่ม Browse; อย่าใช้ path ของเครื่องอื่นแบบตายตัว

## เริ่มใช้งานครั้งแรก

ต้องมี Windows, Python 3.10 ขึ้นไป และ MuMu Player ที่เปิด ADB ได้ จากนั้นเลือกวิธีใดวิธีหนึ่ง:

### วิธีง่ายบน Windows (แนะนำ)

ดับเบิลคลิก `START_HERE.bat` ไฟล์เดียว ตัวเปิดโปรแกรมจะสร้าง `.venv` ของโปรเจกต์และติดตั้ง dependency จาก `requirements.txt` ให้อัตโนมัติ ข้อความใน launcher ใช้ ASCII ทั้งหมดเพื่อไม่ให้ Windows Command Prompt แสดง `��` หรืออ่านภาษาไทยเป็นคำสั่ง

### วิธีผ่าน PowerShell

```powershell
cd "โฟลเดอร์ที่ clone โปรเจกต์ไว้"
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

Dependency ที่ติดตั้งจากไฟล์มีเพียง `Pillow` และ `pynput` ไม่มี OpenCV, NumPy หรือ framework ขนาดใหญ่ ส่วน Tkinter มากับ Python บน Windows และ ADB ต้องมาจาก MuMu Player

## ขั้นตอนใช้งานในโปรแกรม

### 1. เชื่อมต่อ MuMu

1. เปิด MuMu และเปิด ADB ที่ MuMu Settings → Others
2. อยู่แท็บ **เริ่มใช้งานง่าย** แล้วกด **ค้นหา ADB และเชื่อมต่ออัตโนมัติ**
3. หากหาไม่พบ ให้กด **หาไม่เจอ? เลือก ADB เอง** แล้ว Browse ไปที่ `adb.exe` หรือ `adb_server.exe` ของ MuMu
4. เมื่อสำเร็จต้องเห็น serial, model และ Resolution `1280x720`

โปรแกรมไม่เลือก device ที่เป็น `offline`, `unauthorized`, boot ไม่เสร็จ หรืออ่าน `wm size` ไม่ได้

เครื่องนี้ยืนยันแล้วว่าทั้ง `127.0.0.1:5557` และ `127.0.0.1:16416` พร้อมใช้ และ MuMu อาจเพิ่ม `emulator-5556` ให้เห็นใน Dropdown ด้วย ค่า `wm size` รายงานแนวตั้ง `720×1280` แต่โปรแกรมใช้ขนาด screenshot จริง `1280×720` สำหรับพิกัดและ Preview

### Preview และการเล่นบน MuMu จริง

หลังเชื่อมต่อแล้ว กด **เปิด Preview (ไม่ใช้เล่น)** เพื่อตรวจภาพหรือพิกัด:

- คลิกสั้นบนภาพ = Android Tap
- กดเมาส์ค้างอย่างน้อย 250 ms = Hold
- ลากเมาส์ = Swipe
- ภาพไม่ถูกบันทึกลง disk และแสดง FPS/แหล่งภาพจริงที่มุมขวาบน
- Preview ผ่าน ADB ไม่ถึง 25 FPS อย่างเสถียร จึงไม่ใช้เป็นหน้าจอเล่นเกม
- ระหว่าง Recording การคลิกทุกตำแหน่งจะบันทึกเป็น Required event: ใกล้ปุ่มจะเป็น Jump/Slide ตำแหน่งอื่นเป็น Tap/Hold พร้อมพิกัด
- สามารถเล่นและคลิกบนหน้าต่าง MuMu จริงได้โดยไม่ต้องเปิด Live View; global mouse recorder จะจำการกดให้

### 2. สร้าง Pattern และตั้ง Auto Sync

เมื่อจบการอัดแล้วเลือก **สร้าง Pattern ใหม่** งานใหม่จะเริ่มแบบ Set Zero โดยไม่มี Safe Zone จาก Pattern ที่ใช้อัดติดมาด้วย หากต้องการ Safe Zone ให้สร้างเองภายหลังในแท็บขั้นสูง ส่วนการเลือก **บันทึกทับ Pattern ที่มีอยู่** จะยังคงพฤติกรรม Safe Zone ของงานอัดนั้นไว้

1. ที่แท็บ **เริ่มใช้งานง่าย** กด **ใช้ค่าจากภาพนี้**
2. โปรแกรมจะใส่ Jump `(160,635)`, Slide `(1115,635)` และ Pause ROI `(1165,5,62×62)` ให้ทันที
3. โปรแกรมมี Pause template จากภาพนี้ให้แล้ว หากหน้าตา Pause ในเกมไม่เปลี่ยนสามารถใช้ได้ทันที
4. หาก Pause ของ Stage ต่างกัน ให้เปิดแท็บ **ตั้งค่า Pattern ละเอียด** → **สร้าง/อัปเดต Pause ของ Stage**, ตั้งชื่อ และเลื่อนกรอบคงที่ 62×62 ให้ครอบปุ่ม
5. เลือก Template ที่สร้างไว้ได้จาก Dropdown **Pause ของ Stage**; Pattern จะจำตัวเลือกนั้นไว้

ค่าแนะนำเริ่มต้น:

```text
Threshold = 0.82
Poll = 20 ms
พบต่อเนื่อง = 2
Timeout = 25 s
ดีเลย์หลังพบ Pause = 300 ms (โหมดคงที่ แนะนำ)
```

Pattern ที่สร้างใหม่ใช้ `300 ms` เป็นค่าเริ่มต้น ส่วน Pattern เดิมจะเก็บ Delay ที่เคยบันทึกไว้เพื่อไม่เปลี่ยนจังหวะย้อนหลัง

Pattern เดิมที่อัดด้วย Delay `0 ms` ต้องเล่นด้วย `0 ms` ต่อไป ค่า Delay ต้องเหมือนตอนอัดเสมอ มิฉะนั้น Event ทั้งชุดจะเหลื่อมตามค่าที่เปลี่ยน

ค่า Threshold, Poll และจำนวนเฟรมที่บันทึกใน Pattern จะถูกโหลดกลับมาตรงตัว โปรแกรมไม่เปลี่ยนกลับเป็น preset เงียบ ๆ อีก หากต้องการค่ามาตรฐานให้กดปุ่ม preset เอง

Auto Sync ไม่เทียบภาพเต็มจอ แต่ใช้เฉพาะ Pause ROI พร้อมตรวจคะแนนรวม, normalized structure และเส้นเด่นของไอคอน พื้นหลังเทศกาล ด่าน คุกกี้ และข้อความจึงเปลี่ยนได้ หากไอคอน Pause เหมือนเดิมให้ใช้ `ค่าเริ่มต้น 1280×720`; ถ้าตัวไอคอนเปลี่ยนให้สร้าง Pause Stage ใหม่แล้วเลือกจาก Dropdown

Pause Template ที่สร้างใหม่ทุก Stage ล็อกขนาด Crop เป็น `62×62 px` ผู้ใช้เลื่อนกรอบได้แต่ย่อ/ขยายไม่ได้ และตอนตรวจจริงระบบทำให้ภาพปัจจุบันมีขนาดตรงกับ Template ก่อนคำนวณคะแนนเสมอ รายการ Stage เก็บใน `pause_profiles.json`; Pattern เดิมที่ไม่มีชื่อ profile ยังเปิดและเล่นได้ตามเดิม

เส้นทาง **Fast ROI** อ่านกรอบ Pause จากหน้าต่าง MuMu โดยตรงด้วยรอบตรวจเป้าหมาย `20 ms` ขณะ MuMu อยู่ด้านหน้า หลังผ่าน 2 เฟรมระบบยึดเวลาเริ่ม Capture ของเฟรมแรก ระบบใช้ Threshold ช่องเดียวจริงทั้ง Fast ROI และ ADB: คะแนนรวมใช้ค่าที่กรอก, เส้นใช้ `Threshold - 0.06`, โครงใช้ `Threshold - 0.10` จึงไม่มีเกณฑ์ลับที่ทำให้ปรับแล้วผลไม่เปลี่ยน สำหรับ MuMu หน้าต่างแนวตั้ง ระบบหา display child แล้ว fit เกม 16:9 ภายใน content เมื่อ Fast ROI ใช้งานไม่ได้ต่อเนื่อง ระบบจึงใช้ ADB Raw verification (PNG สำรอง) และพักเพียง `100 ms` ก่อนตรวจรอบถัดไปแทน `600 ms` เดิม

เพื่อให้ latency คงที่ ให้ใช้ปุ่ม **คงที่ • Delay 300 ms (แนะนำ)** ระบบจะกำหนด `จุดเริ่ม Pattern = Pause เฟรมแรก + 300 ms` ทั้งตอนอัดและตอนเล่น ไม่ว่า Detector จะประมวลผลเสร็จใน 40 หรือ 180 ms เวลาที่เหลือจะถูกปรับอัตโนมัติ หาก Fast ROI ทำงานดีและต้องการเร็วที่สุด ใช้ **เร็วสุด • Delay 0 ms** ช่อง Delay ปรับเองได้ `0–3000 ms`

รุ่นล่าสุดใช้ detector แบบแข่งสองทางเฉพาะช่วงรอ Pause: Fast ROI ได้ช่วงนำคงที่ `80 ms` เพื่อจบโดยไม่แย่งทรัพยากร จากนั้น ADB Raw native จะเริ่มเสมอเพื่อกู้เมื่อ Fast ROI เปิดได้แต่พลาดเฟรมหรือพิกัด โดยไม่ต้องรอสถานะ Fast path ล้ม และหยุด ADB เมื่อ Sync สำเร็จ การ Poll ของ Fast ROI นับแบบ start-to-start และเฟรมยืนยันถัดไปตรวจแบบ burst หลัง `5 ms`

ช่อง `ลองตรวจใหม่ทุก` ไม่ได้หยุด Auto Sync เมื่อหมดเวลา แต่กำหนดความยาว detector หนึ่งรอบ เมื่อหมดรอบโปรแกรมจะ re-arm และตรวจต่ออัตโนมัติ F9 ยังเริ่มเองได้และ F8 ยังหยุดได้ จึงใช้ Loop แบบไม่เฝ้าหน้าจอได้โดยไม่ค้างรอ F9 หลังพลาดครั้งเดียว

อย่าตัดสิน Auto Sync จากภาพเดียว ให้หยุดอัด/เล่นก่อนแล้วกด **ทดสอบจริง 8 เฟรม (เปิด MuMu อัตโนมัติ)** โปรแกรมจะเปิด MuMu และนับเฉพาะภาพ `MuMu Window ROI` จริง ผลจะแสดงจำนวนเฟรมที่ผ่าน คะแนนต่ำสุด/เฉลี่ย/สูงสุด, Capture median/max และ `เกณฑ์ที่ใช้จริง` ทั้งรวม/เส้น/โครง ภาพดำ sentinel และ ADB จะไม่ถูกนับในผลทดสอบ

ผลจากภาพที่ผู้ใช้ส่งรอบล่าสุด `รวม 0.642` และ `0.683` เป็นหน้าร้านค้า/หน้าเตรียมที่ไม่มี Pause จึงควรได้ 0/8 ส่วนภาพในด่านที่เห็น Pause จริงได้ `รวม 0.9366` และผ่าน Threshold `0.82` หน้าทดสอบจะแยกข้อความ `ไม่พบ Pause ในภาพปัจจุบัน` ออกจาก `พบ Pause แต่คะแนนแกว่ง` เพื่อไม่แนะนำให้แก้ ROI ผิดหน้า

### 3. อัด Pattern

1. กด `F6` แล้ว `PRE-SYNC` จะเริ่มนับเวลาและเก็บ Event ทันที
2. เล่นบน MuMu จริง; Tap/Hold ก่อน Pause จะเก็บเป็น `pre_sync`
3. เมื่อ Auto Sync สำเร็จหรือกด `F9` ระบบเริ่ม timeline `synced` ที่ `t = 0`
4. แถบเปลี่ยนเป็น `REC` และ Event หลังจากนี้จะเก็บเป็น `synced`
5. ทุก Tap/Hold บน MuMu จริงจะเก็บพิกัดและระยะกด
6. กด `J` เพื่อ Jump หรือกด `K` ค้างเพื่อ Slide ได้เหมือนเดิม
7. ดูตัวนับ Events/Jump/Slide/Tap/Hold ให้เพิ่มระหว่างอัด และดู Keyboard/Jump detector เพื่อยืนยันการจับปุ่ม
8. เมื่อจบเกมและระบบพบ XP พร้อมยืนยันว่า Pause หาย แถบเปลี่ยนเป็น `POST-GAME`
9. หลังจากนั้นคลิกปุ่ม OK/เมนูต่อด้วยเมาส์ โปรแกรมเก็บเฉพาะ Tap/Hold; J/K จะไม่ถูกบันทึกเป็น Jump/Slide
10. กด `F7` เพื่อหยุดเป็น Draft แล้วเลือกสร้าง Pattern ใหม่หรือบันทึกทับ Pattern ที่มีอยู่

#### เลือกที่บันทึกหลัง F7

- `F7` จะไม่เขียนทับ Pattern ปัจจุบันทันทีอีกแล้ว
- ตัวเลือกเริ่มต้นคือ **สร้าง Pattern ใหม่** พร้อมชื่อที่ไม่ซ้ำ
- เลือก **บันทึกทับ Pattern ที่มีอยู่** ได้จาก Dropdown พร้อมคำเตือนสีแดง
- กด **เก็บเป็น Draft** เพื่อปิดหน้าต่างโดยยังรักษางานในหน่วยความจำ แล้วกด `F7` เพื่อเปิดใหม่
- กด **ไม่บันทึก (ทิ้งงานอัด)** เมื่อต้องการทิ้งรอบนั้นจริง โปรแกรมจะถามยืนยันอีกครั้งและไม่เขียนทับ Pattern ใด
- หากมี Draft ค้าง โปรแกรมจะกันไม่ให้เริ่มอัดรอบใหม่และเตือนก่อนปิดโปรแกรม

ทุก Event ที่อัดจะเป็น **REQUIRED** โดยอัตโนมัติ: Chance 100%, Jitter 0 และไม่มี `none`

#### Phase หลังจบเกมและ XP fallback

- ค่าเริ่มต้นตรวจคำว่า XP ใน ROI `(155,450,130×75)` จากภาพ Result ที่ให้มา
- แต่ละรอบ Capture หนึ่ง screenshot แล้ว crop เพียง XP ROI กับ Pause ROI จึงเบาและไม่ใช้ OCR ทั้งจอ
- ต้องพบ XP ผ่านคะแนนรวม/โครง/เส้น 3 เฟรมต่อเนื่อง และ Pause ต้องต่ำกว่า `0.80`
- ตรวจเร็ว: ถ้า XP มาเร็วกว่าจังหวะ Pattern จะตัด Jump/Slide ที่ยังเหลือทันที
- ตรวจช้า: ถ้า XP มาหลัง Event synced สุดท้าย ระบบรอได้อีกตาม `timeout_seconds` แล้วค่อยเล่น Tap/Hold `post_game`
- ไม่พบ XP: หยุดอย่างปลอดภัยโดยไม่ส่ง Tap หลังเกมไปหน้าที่ไม่รู้จัก
- หน้า Result ของเครื่อง/สเกลต่างจากภาพอ้างอิง: เปิดหน้า Result แล้วกด **Capture กรอบ XP เอง** และ **ทดสอบหน้า Result ตอนนี้**

#### Surprise Card หลังจบด่าน

- เปิด **แก้ Surprise Card อัตโนมัติ** เพื่อแยกหน้า Result ออกจากเกมการ์ดก่อนส่ง Post-game Tap
- หากเปิดหน้า Challenge ค้างไว้ ให้กด **ทดสอบ/เล่น Surprise Card ตอนนี้ (ไม่รัน Pattern)** เพื่อแก้เฉพาะเกมการ์ด 3 รอบ; ปุ่มนี้ไม่เริ่ม Pattern, Sync, Result detector หรือ Post-game Events และกด `F8` เพื่อหยุดได้
- รองรับ Layout `5 ใบ / 1 คำตอบ` และ `6 ใบ / 2 คำตอบ` ทั้งชื่อ Jumping/Sliding โดยเปรียบเทียบการ์ดในรอบเดียวกัน ไม่ผูกจำนวนใบกับชื่อเกมและไม่จำหน้าตาตัวละคร
- Layout 6 ใบหาเป็นกลุ่มภาพ `4+2` โดยตรงและใช้ cluster margin `1.8`; จึงรองรับตัวละครขนาดเล็กโดยไม่พึ่งคะแนนความต่างแบบค่าสัมบูรณ์
- Sliding คลิกสองใบทีละใบ ค่าเริ่มต้นเว้น `500–900 ms`; ไม่ส่ง Tap พร้อมกัน
- หลังตอบครบหนึ่งรอบจะรอ `1800–2200 ms` และต้องเห็นภาพหรือตัวนับรอบเปลี่ยนก่อนตอบรอบถัดไป
- ถ้าคำตอบไม่ตรงกันสองเฟรม, จำนวนการ์ดผิด, confidence ต่ำ หรือหน้าเดิมค้าง ระบบจะไม่เดาและไม่คลิกซ้ำ
- ผ่านครบ 3 รอบแล้ว ระบบยังต้องรอ XP Result จริงก่อนเริ่ม Event `post_game`

หากเปิด **Tap Slide รัว → รวมเป็น Hold** โปรแกรมจะรวม Slide taps หรือ Tap ตำแหน่งใกล้กันที่ห่างไม่เกิน 180 ms เป็น Hold เดียว โดยไม่รวม Jump taps เพราะการกระโดดซ้อนอาจมีความหมาย

#### Single Jump และ Double Jump

- J ทุกครั้งหรือ Tap ปุ่ม Jump ทุกครั้งถูกเก็บเป็น Jump Event แยกกัน
- Double Jump จึงเป็น Jump 2 Events ที่รักษาระยะห่างจริง ไม่ถูกแปลงเป็น Hold
- ถ้าสองครั้งล่าสุดอยู่ phase เดียวกันและห่างไม่เกิน 650 ms บรรทัด `Jump detector` แสดง `DOUBLE JUMP` พร้อม gap
- Global listener อ่านได้ทั้ง `char` และ Windows virtual-key 74/75
- เมื่อ MuMu active โปรแกรมไม่ส่ง ADB tap ซ้ำ แต่บันทึก Event จาก keymap ของ MuMu โดยตรง
- ตอนปล่อย J โปรแกรมล้าง pressed state เสมอ จึงกด J ซ้ำได้ต่อเนื่อง

### Library มาโคร

แท็บ **Library มาโคร** รองรับ:

- Save และ Load
- Rename และ Delete
- แสดงจำนวน Events, ความยาว Pattern, จำนวนครั้งที่กดเล่น และเวลาที่เล่นล่าสุด
- Import `.json` หรือ `.zip`
- Export `.json` หรือ ZIP bundle ที่รวมทั้ง Pause template และ Result XP template
- หาก Import ชื่อซ้ำ โปรแกรมจะสร้างชื่อ `_2`, `_3` โดยไม่เขียนทับของเดิม

### 4. เพิ่มความสุ่มอย่างปลอดภัย

1. ไปแท็บ **Random และ Safe Zone (ขั้นสูง)**
2. เลือก Pattern ที่ช่องบนสุด แล้วกด **โหลด Pattern นี้**
3. ดู Event บน Timeline สามเลน: ก่อน Sync, หลัง Sync และหลังจบเกม
4. ลากช่วงบนเลนหลัง Sync แล้วกด `สร้าง Safe Zone (N Events)`
5. คลิก Zone สีเขียวเพื่อเลือก/แก้ไข หรือกด **ลบ Zone ที่เลือก**; หากมี Safe Random โปรแกรมจะถามก่อนลบ Event ที่ผูกอยู่ด้วย
6. แท็บเลื่อนลงได้เพื่อดูตาราง Events/Safe Zones และปุ่มบน Timeline ยังใช้ได้ที่ความสูงหน้าต่างขั้นต่ำ
7. เพิ่ม Event แล้วเลือก Class `safe_random` จากนั้นเลือก `optional_action` หรือ `choice`
8. ระหว่างเล่น เส้น Playhead จะเดินในเลนของ phase ปัจจุบัน เวลาเริ่มใหม่เมื่อเข้า phase ถัดไป และ Timeline จะเลื่อนตามอัตโนมัติ
9. ใช้ปุ่ม **ทำสำเนา** ที่ตาราง Event หรือ Safe Zone แล้วปรับเวลา/ค่าในหน้าต่างก่อนบันทึกได้

Safe Zone ถูกเก็บอยู่ใน JSON ของ Pattern ที่เลือก ไม่ใช้ร่วมกับ Pattern อื่น การอัดใหม่จาก Pattern ที่มี Safe Zone จะยังคง Zone ไว้ แต่ Event ที่อัดจะเป็น Required ตามจริงและไม่ถูกเปลี่ยนเป็น Random เอง

โปรแกรมจะไม่ยอมบันทึก Safe Random เมื่อ:

- ยังไม่มี Safe Zone หรือ Event อยู่นอก Zone
- Slide รวม Jitter แล้วสิ้นสุดนอก Safe Zone
- อยู่ใกล้ Required Event กว่า safety gap
- Jitter ทำให้เวลาออกนอก Zone (กรณีนี้โปรแกรมจะลด Jitter ให้อัตโนมัติเมื่อทำได้)
- Event ใกล้ Required น้อยกว่า safety gap เริ่มต้น 250 ms
- Weight ติดลบหรือรวมเป็นศูนย์

Required Event สามารถอยู่ใน Safe Zone ได้ เพราะ Zone เป็นเพียงขอบเขตที่ “อนุญาต” ให้สร้าง Safe Random ไม่ใช่คำสั่งให้เปลี่ยน Event ทุกตัวเป็น Random

### เปิด Pattern เก่าที่มี Event ไม่ผ่านกฎ

- โปรแกรมจะเปิดเป็น **โหมดซ่อม Pattern** แทนการปฏิเสธทั้งไฟล์
- Event ที่มีปัญหาจะแสดงเป็นแถวสีแดง พร้อมสาเหตุในคอลัมน์ `Validation`
- ดับเบิลคลิกแถวหรือกด **แก้ไข Event ที่เลือก** เพื่อปรับเวลา, Chance, Jitter หรือ Duration; อีกทางคือขยาย Safe Zone ให้ครอบการทำงานจนจบ
- กด **บันทึก Pattern** ได้แม้ยังแก้ไม่ครบ ระบบจะสำรองต้นฉบับเป็น `.json.repair.bak`, บันทึกความคืบหน้าแบบ atomic และเปิดซ่อมต่อครั้งหน้าได้
- Play และ Record จะยังถูกบล็อกด้วย validation เดิมจนกว่าทุก Event ถูกต้อง เพื่อไม่ให้คำสั่งที่ไม่ปลอดภัยเข้าเกม
- หน้าต่างย่อย **เพิ่ม/แก้ Event** และ **เพิ่ม/แก้ Safe Zone** มี scrollbar และเลื่อนได้ด้วยล้อเมาส์หรือ trackpad แม้ย่อหน้าต่างให้เตี้ย

### 5. เล่น Pattern

1. เลือก Pattern และจำนวนรอบ
2. ตรวจว่า Events มากกว่า 0; โปรแกรมจะไม่ยอมเล่น Pattern ว่าง
3. กด **เล่น**
4. โปรแกรมตรวจ device/resolution แล้วเล่น Event `pre_sync` ก่อน
5. จากนั้นรอ Auto Sync หรือกด `F9`
6. เมื่อ Sync แล้วจึงเล่น Event `synced`
7. Result detector เริ่มเฝ้า XP หลัง Sync; เมื่อพบจะตัดคำสั่งเกมที่เหลือและเล่นเฉพาะ Tap/Hold `post_game`
8. ถ้า Event เกมหมดก่อนพบ XP HUD จะแสดง `รอหน้า Result`; timeout แล้วหยุดโดยไม่ Tap
9. ถ้ารอบตรวจ Auto Sync หมดเวลา โปรแกรมจะ re-arm และตรวจรอบใหม่เอง; `F9` ใช้เฉพาะเมื่อผู้ใช้ต้องการเริ่มเอง
10. กด `F8` ได้ทุกสถานะเพื่อหยุด worker และ ADB shell

การจัดเวลาใช้ absolute timestamp จาก sync anchor จึงไม่สะสมความคลาดเคลื่อนจาก Event ก่อนหน้า

ช่อง **เวลาก่อน Auto Sync** เลือกได้สองแบบ: `fixed` ใช้ค่า Fixed เดิมทุกครั้ง หรือ `random` สุ่มระหว่าง Min–Max เฉพาะรอบที่ทำ Sync ค่า **ห่างอย่างน้อย** จะกันค่าที่ใกล้ค่าล่าสุด เช่นช่วง `300–500 ms` และระยะห่าง `50 ms` จะไม่สุ่ม `300` แล้วได้ `310`; ระบบจำย้อนหลังตามจำนวนที่กำหนด ค่านี้ไม่เลื่อน Event `synced`, ไม่เปลี่ยน `post_game` และไม่เปลี่ยน Delay ระหว่าง Loop

HUD ระหว่างเล่นอัปเดตทุกประมาณ 100 ms โดยแสดงเวลาปัจจุบัน/ความยาวช่วง, phase ปัจจุบัน, รอบ, Event ปัจจุบัน/ทั้งหมด, progress bar และเวลาที่เหลือ ช่วงรอ Sync จะแสดงเวลาที่รอและข้อความให้กด F9 ได้ทันที

### Loop Pattern

ตั้ง `รอบ`, `Loop จน F8`, `Delay ms`, `ก่อน Sync +ms` และ `Sync/รอบ` ได้จากหน้าหลักหรือหน้าตั้งค่า Pattern ค่าเหล่านี้บันทึกอยู่ใน Pattern และติดไปกับ Import/Export

## แก้ปัญหาเบื้องต้น

- **ไม่พบ ADB:** ใช้ Browse เลือก ADB ของ MuMu โดยตรง ห้ามเลือกไฟล์ที่เรียก `adb devices` ไม่ได้
- **ไม่พบ Device:** ตรวจว่า MuMu เปิดอยู่, ADB เปิดอยู่ และพอร์ตตรงกับหน้า Settings
- **Device offline/unauthorized:** restart MuMu/ADB แล้วค้นหาใหม่ โปรแกรมจะไม่เลือก device นี้เอง
- **Resolution ไม่ตรง:** อย่าฝืนใช้แบบเงียบ ๆ ให้ยกเลิก ปรับพิกัด และ Capture template ใหม่
- **Template หาย/ROI เกินภาพ:** เปิดด่านแล้ว Capture Pause Template ใหม่
- **Auto Sync ยังไม่พบ Pause:** ระบบเริ่มตรวจรอบใหม่เอง ดูข้อความรอบและคะแนนดีที่สุด; F9 เป็นตัวเลือก ไม่ใช่สิ่งที่ต้องมากดทุกครั้ง
- **Auto Sync ยังช้า:** โฟกัสหน้าต่าง MuMu เพื่อให้ใช้ `MuMu Window ROI`; ถ้าขึ้น `ADB fallback` จะช้ากว่า
- **ตรวจแล้วช้า/คะแนนแกว่ง:** หยุดอัด/เล่น เลือก Pause Stage ให้ถูก แล้วใช้ปุ่มทดสอบ 8 เฟรม โปรแกรมจะเปิด MuMu เองและนับเฉพาะ Fast ROI จริง
- **แต่ละ Stage ใช้ Pause ต่างกัน:** สร้างชื่อ Stage แยกกัน แล้วเลือกจาก Dropdown `Pause ของ Stage`; ชื่อเดิมใช้สำหรับอัปเดตภาพของ Stage นั้น
- **ต้องการเริ่มตรวจ Pause ช้าลงอย่างเดียว:** ใส่ `เพิ่มเวลาก่อน Auto Sync`
- **ต้องการให้จุดเริ่ม Pattern คงที่หลังเห็น Pause:** ใช้ `คงที่ • Delay 300 ms` แล้วอัดและเล่นด้วยค่าเดียวกัน
- **ปรับ Threshold แล้วผลไม่เปลี่ยน:** กดทดสอบ 8 เฟรม ดู `เกณฑ์ที่ใช้จริง`; รุ่นนี้ขยับเกณฑ์รวม/เส้น/โครงตามค่าที่กรอกทั้งหมด
- **Auto Sync ไม่ทำงาน:** รุ่นนี้ใช้ Fast ROI + ADB Raw แข่งกันและ re-arm เอง หากยังไม่พบให้ส่งคะแนนดีที่สุด/แหล่งภาพ/เลขรอบที่แสดง โดยไม่ต้องลด Threshold
- **Loop พังหลัง Auto Sync พลาด:** ปิดโปรแกรมเก่าแล้วเปิดใหม่ Timeout รุ่นนี้ไม่เปลี่ยนไปค้าง F9 แต่เริ่ม detector รอบใหม่อัตโนมัติ
- **Auto Sync เร็วผิดหน้า:** ใช้ `0.82 / 20 / 2`; ROI ต้องครอบเฉพาะ Pause icon ไม่ใช่ฉาก
- **Safe Zone ลากหลาย Event แล้วปุ่มหาย:** รุ่นนี้แยกปุ่มไว้คนละแถวและย่อรายการเหลือ 4 ตัวอย่างแล้ว; ปุ่มต้องแสดงเป็น `สร้าง Safe Zone (N Events)` ตลอด
- **เลือกหรือลบ Safe Zone ไม่ได้:** เลือก Pattern ที่ช่องบนสุด คลิกกรอบเขียวหรือแถว Safe Zone แล้วกด `ลบ Zone ที่เลือก`; ถ้ามี Event ผูกอยู่จะมีหน้าต่างยืนยัน
- **ไม่ต้องการบันทึกรอบที่อัด:** กด `ไม่บันทึก (ทิ้งงานอัด)` และยืนยัน งาน Draft รอบนั้นจะถูกล้างโดยไม่แตะ Pattern เดิม
- **F7 แล้วไม่ต้องการทับ Pattern:** เลือกสร้างใหม่ (ค่าเริ่มต้น) หรือเก็บ Draft แล้วกลับมาเลือกภายหลัง
- **ด่านหรือเทศกาลพื้นหลังเปลี่ยน:** ไม่กระทบเมื่อ Pause icon/ROI ยังเหมือนเดิม เพราะระบบไม่เทียบเต็มจอ
- **ไม่ตรวจพบ Result:** ค้างหน้า Result แล้วทดสอบ XP; ถ้าคะแนนต่ำให้ Capture คำว่า XP ใหม่
- **Result timeout:** โปรแกรมตั้งใจไม่ Tap เพื่อความปลอดภัย ให้เพิ่มเวลารอหรือ Capture XP ใหม่แทนการลด Threshold มากเกินไป
- **พบ Pause แล้ว Pattern จบทันที:** ตรวจ Events ใน Library; ถ้าเป็น 0 ให้อัดใหม่ โปรแกรมรุ่นนี้จะกันไม่ให้กดเล่น Pattern ว่าง
- **Preview FPS ต่ำ:** ไม่ใช้ Preview เล่นเกม ให้เล่นบน MuMu จริง
- **Events ไม่เพิ่ม:** ดู `Mouse recorder`; ถ้าจับได้ต้องแสดงพิกัด MuMu และคำว่า `กำลังบันทึก`
- **J จับได้ครั้งเดียว:** ปิดหน้าต่างโปรแกรมเดิมแล้วเปิดใหม่ ตรวจว่า `Keyboard recorder` แสดง J DOWN แล้ว J UP และ Jump เพิ่มทุกครั้ง
- **Double Jump ไม่ถูกจับ:** กด/แตะ Jump สองครั้งภายใน 650 ms; `Jump detector` ต้องขึ้น DOUBLE และ Event table ต้องมี Jump สองแถว
- **Slide ไม่ตอบสนองระหว่างอัด:** MuMu/Android บางรุ่นอาจไม่รองรับ `input motionevent`; ต้องทดสอบบนเครื่องจริงและปรับวิธี input หากจำเป็น
